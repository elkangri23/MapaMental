- **Seguridad (T-015/T-026):** revisión estática, build y `npm audit` sin vulnerabilidades conocidas. En Fastify, un hostname que resolvió a loopback se rechazó con HTTP 400 y cero conexiones al listener canario; una simulación separada confirmó pinning DNS. Una inyección ENOSPC tras crear un parcial confirmó limpieza, proyecto intacto y reintento; la API devolvió HTTP 507 `INSUFFICIENT_STORAGE` sin revelar la ruta del proyecto. Siguen pendientes la limpieza bajo ACL/disco real, la carrera DNS/socket en HTTP y recorridos OIDC/MFA; ver [`informe`](reviews/2026-11-17-security-audit.md).
- **T-009/T-010:** hubo evaluaciones anteriores con FreeLLMAPI y varios modelos, incluidos ciclos de sugerencia, vista previa, aplicación y deshacer. En la última repetición, Ollama y LM Studio no estaban activos y FreeLLMAPI agotó el tiempo a los 60 segundos. La calidad quedó sin reevaluar en esa petición.
- **T-013:** ZIP e instalador compilados; prueba aislada de instalación, servicio HTTP 200, parada y desinstalación correcta. Los artefactos se regeneraron tras la corrección T-016; falta repetir el smoke test de esta compilación, probar actualización desde una versión posterior y comprobar conservación de proyectos.
- **T-015:** build y verificaciones de host/SSRF documentadas: matriz representativa IANA, redirección rechazada, hostname que resuelve a loopback bloqueado por HTTP antes de conectar, TLS/SNI y límite de tres generaciones simultáneas. La simulación DNS determinista confirmó pinning del socket. La inyección ENOSPC confirmó limpieza y reintento; la ruta de proyecto respondió 507 con mensaje seguro y sin ruta interna. Falta cubrir disco real/limpieza por ACL y la carrera DNS/socket en HTTP. [`THREAT_MODEL.md`](THREAT_MODEL.md) sigue siendo un modelo inicial, no una evaluación formal.
- **T-016:** Chrome confirmó nombres en español para conexiones/nodos, recorrido con Tab, Lighthouse 100/100 Accessibility en mapa, presentación y lista paginada de 10.000 ideas, controles con nombre y reflujo sin solapamiento a 320 px. El zoom mínimo móvil mantiene botones de mapa de 24 px y la lista conserva el foco al paginar. Siguen pendientes lector de pantalla real y revisión completa de teclado, contraste y estados; ver [`informe WCAG`](reviews/2026-11-17-wcag-aa-audit.md).
- **T-017:** se corrigieron colisiones de copias al reintentar guardados/restauraciones y ahora se intenta retirar el destino parcial si falla una copia o su verificación. La API informa ENOSPC como HTTP 507, con mensaje útil sin exponer detalles del archivo. La inyección tras crear un parcial confirmó retirada, proyecto intacto y reintento válido. Siguen pendientes otros puntos ACL, disco lleno físico e interrupciones.
- **T-028 — Rendimiento:** en móvil Fast 3G/CPU 4×, gzip redujo el JSON del proyecto de 1,86 MB a 134 KB; una corrida LCP 6.910→4.817 ms no demuestra causalidad. La lista paginada monta 250 botones (871 elementos DOM) y Lighthouse da 100/100. El autosave comparte snapshots memoizados. En fixture pequeño, F2/Enter/Escape, guardado y etiquetas accesibles quedaron verificados. En canvas de 10.000 se confirmó borrador local y autosave. La nueva muestra de producción registró `keydown` F2 de 703 ms (3 ms de input delay, 584 ms de procesamiento, 115 ms de presentación) frente a 2.407 ms en desarrollo, pero ambas son muestras únicas con foco programático y tecla de DevTools; no prueban mejora causal ni son INP de campo. La interacción sigue por encima de 500 ms. El heap ~66,2 MB de una ventana no es comparable entre builds. Próximo: entrada física repetible, separar edición/autosave, identificar trabajo/layout y comparar heap post-GC. Ver [informe](reviews/2026-11-17-performance-audit.md).
