# Proyectos, guardado y recuperación

**Estado: persistencia base recorrida manualmente; migraciones 0→1 y 2→3, copia y reintento de reemplazo verificados en almacenamiento aislado.** La UI permite seleccionar/crear proyectos, autosave de mapa y diapositivas, consultar/restaurar copias válidas y aplicar/deshacer una propuesta IA. En almacenamiento temporal aislado se verificó migración 0→1 y restauración desde UI; en la continuación se restauró desde UI el backup inicial de una presentación de cinco diapositivas y se confirmó revisión nueva con copia preservada. También se recorrieron aplicación/deshacer del flujo IA y persistencia de diapositivas/bloques tras recarga. Se recorrió v2→v3 conservando la revisión y copia byte por byte, y los fallos `EPERM` de reemplazo con conservación de backup y reintento. El modo de solo lectura para esquemas futuros se verificó con fixtures aislados; sigue pendiente recorrer el deshacer IA tras reiniciar el servicio.

## Formato actual

Cada proyecto tendrá una carpeta propia bajo `Documentos\EspacioVisual\Proyectos` (ruta configurable), con `project.json` versionado y una carpeta `backups`. En v1 solo se admitirán volúmenes locales fijos; se rechazarán rutas UNC y unidades extraíbles. El esquema actual es v3. El JSON guarda ID, revisión, mapa, presentación ordenada, conversación y sugerencias; no guarda claves de proveedor. Cada diapositiva tiene `id`, `title`, `subtitle`, `body`, `bullets` y `sourceNodeIds`; opcionalmente incluye hasta ocho `diagramSteps` y ocho `mockFields` (etiqueta y valor ficticio, acotados). Estos bloques son visuales/editables y no recogen ni transmiten datos. El validador limita longitud y cantidad y exige que los IDs de origen existan en el mapa. Los cambios pasan por autosave y copias. La exportación usa la impresión del navegador; la salida visual todavía no se recorrió.

## Guardado y copias

La conversación guarda hasta 500 mensajes de consultas completadas en el mismo `project.json`. Las copias y restauraciones incluyen ese historial. Si solo cambia la conversación, el servidor conserva el inverso de IA vigente y lo vincula a la nueva revisión.

Aplicar una presentación completa con IA conserva sus diapositivas anteriores en `lastAiDeckUndo` y en la copia previa. El deshacer solo se admite para la revisión vigente. Una edición posterior del mapa o la presentación invalida el deshacer inmediato. La copia previa sigue disponible en el diálogo de recuperación.

El servicio local aplicará autosave tras cambios confirmados. Escribirá y sincronizará un archivo temporal en la misma carpeta, lo volverá a leer y validar, creará y verificará una copia de la revisión actual, y solo entonces reemplazará `project.json`. Si falla el reemplazo, conservará el principal y la copia válida; un reintento reutiliza esa copia si coincide con el archivo vigente. El estado de guardado se mostrará en la UI. Tras éxito conserva hasta 20 copias JSON válidas recientes; los archivos corruptos no cuentan para ese límite. El serializador omite estados de interacción temporales como selección y medición visual. La UI ofrece un panel de recuperación con fecha y revisión; al restaurar pide confirmación, preserva el estado actual y crea una nueva revisión. Si el documento principal no se puede leer, el proyecto aparecerá en el selector con una etiqueta de recuperación; la API permite consultar copias y restaurar una como nueva revisión, y conserva el archivo dañado con extensión `.invalid`.

La última operación IA guarda `lastAiUndo` con la revisión aplicada e IDs de nodos/conexiones que añadió. El validador exige revisión actual, IDs generados por IA, una conexión desde un padre común existente por cada nodo nuevo y ninguna conexión adicional a esos nodos. Una edición normal limpia el inverso antes de validar el nuevo estado; así una edición o eliminación posterior invalida deshacer sin bloquear el guardado. Al aplicar, `saveProject` guarda un backup antes de la revisión nueva; al deshacer, se escribe otra revisión y se limpia el inverso. Restaurar una copia o crear una bifurcación por conflicto limpia los inversos de mapa y diapositiva. El flujo IA se recorrió previamente sin reinicio del servicio; sus casos de edición/validación tras IA quedan pendientes de recorrido.

## Versiones

Cada esquema tendrá `schemaVersion` y migraciones ordenadas. El esquema actual es 3. Las migraciones 0, 1 y 2→3 preservan los campos de proyecto, validan el resultado y generan/verifican una copia previa antes de escribir. Se recorrió 2→3 con un archivo v2 temporal. Si una versión anterior encuentra un esquema más nuevo, la lista marca el proyecto como solo lectura y permite inspeccionar una proyección de campos reconocidos si valida completa; la UI bloquea edición/autoguardado y explica el esquema. Si la estructura futura no se puede proyectar sin pérdida, presenta solo metadatos. La API editable continúa rechazándolo con `PROJECT_FUTURE_SCHEMA`, evitando sobrescrituras.
