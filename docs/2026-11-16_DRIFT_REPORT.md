## docs/designs/espacio-visual-personal.md

- **Restricción de volumen — resuelta parcialmente en 2026-11-16:** ADR-0017 y el inicio del servicio ahora rechazan UNC, tipos de volumen que no sean `Fixed` y buses USB/SD/MMC, iSCSI, Fibre Channel o desconocidos; fallan cerrados si PowerShell Storage no puede resolver el almacenamiento. Se recorrió el volumen local fijo C: y la ruta UNC se rechaza antes del acceso. No se conectó un medio extraíble para verificar ese caso en hardware. La clasificación se realiza al arrancar y requiere reinicio si cambia la topología.
- **Contrato persistido de proyecto y diapositiva — resuelto en 2026-11-16:** ADR-0015 establece el formato JSON v3 ya validado por `ProjectDocument` como canónico. La especificación ahora distingue modelo conceptual y nombres/campos serializados: `conversation`, nodos/aristas React Flow y `PresentationSlide` con campos de bloques planos. No se cambió ni migró el esquema. Los cambios futuros de estructura requieren subir versión y migrar.
- **Contexto del modelo (parcial):** `buildProjectAiContext` comparte entre UI y servidor hasta 50 ancestros, 350 relaciones y contenido de hasta 20 diapositivas vinculadas (500 caracteres cada una, 6.000 totales), además de un resumen estructural determinista: idea central y hasta ocho etiquetas de ramas de 120 caracteres. La vista previa y el payload del proveedor se verificaron iguales con mock. Falta validar calidad con un modelo real y truncamiento con mapas/contenido grandes.
- **Errores de API — resuelto en 2026-11-16:** ADR-0014 fija `{code,message,correlationId}` para errores JSON y errores terminales SSE. El hook central normaliza errores JSON de rutas/middleware/Fastify, preserva los campos de estado, oculta mensajes 5xx y reutiliza el ID de petición de los registros. Los errores SSE se tiparon con el mismo contrato. Se verificaron manualmente las respuestas 404 y 403; el evento SSE aún requiere un recorrido con proveedor simulado.
- **Persistencia y contrato serializado — resuelto en 2026-11-16:** ADR-0015 declara `ProjectDocument` v3 como formato persistido canónico. El diseño conceptual no obliga a guardar una estructura distinta; cambiarla requerirá versión y migración explícitas.
- **Trazabilidad de operaciones:** el diseño prevé correlacionar proveedor, validación, commit y guardado sin registrar prompts. Ahora hay un registro local acotado de eventos de autenticación y se eliminan los query strings de los logs HTTP, pero no se registra la secuencia proveedor→validación→commit→guardado para cambios IA.
- **Dirección de escucha — resuelto:** ADR-0013 establece `::1` para el servicio, `localhost` para el origen WebAuthn y el callback `[::1]` para OIDC. Se actualizaron la especificación y los ADR 0001/0009; la prueba con un IdP real sigue pendiente.
- **Capacidad objetivo (medición parcial):** el diseño fija una meta inicial de 1.000 nodos y 100 diapositivas; el límite efectivo sigue en 10.000 nodos. En Windows/Node 24 se guardó desde `saveProject` un fixture de 1.005.189 bytes con 1.000 nodos, 999 aristas y 100 diapositivas en ocho ejecuciones de 63–142 ms, incluyendo copia previa y escritura durable. No incluye serialización/transferencia HTTP ni demuestra el rendimiento de otros discos; el límite efectivo frente a la meta de diseño sigue sin decisión explícita.
