# Privacidad y seguridad local

**Estado: sesión local y rutas de proveedor/proyectos/IA protegidas; recorrido funcional parcial con proveedor simulado.**

La línea base de controles y pendientes para OWASP Top 10:2025 y WCAG 2.0 AA está en [`COMPLIANCE.md`](COMPLIANCE.md). No se declara certificación ni conformidad hasta completar las revisiones indicadas.

- Fastify limita los cuerpos de petición a 8 MiB, parámetros a 128 caracteres y conexiones/solicitudes; los registros redactan Authorization, Cookie y x-api-key. Los errores internos devuelven mensajes genéricos y el log registra solo estado, código y nombre de error, nunca cuerpo, prompt o clave. En producción se envían CSP, nosniff, X-Frame-Options, Permissions Policy, CORP/COOP y Referrer Policy.
- Los endpoints de proyecto, proveedor, sesión e IA rechazan cuerpos nulos/primitivos, parámetros e identificadores con formato incorrecto antes de operar. Se recorrieron ocho solicitudes inválidas con sesión temporal y todas devolvieron 400; la matriz completa de host/origen/cookie y tamaño aún está pendiente.
- Proyectos y perfiles se validan con límites a campos, colecciones, IDs, posiciones y tamaño del archivo/configuración. Las acciones de IA y restauración fuerzan guardar antes de consumir el estado persistido, evitando que el contexto o la restauración salten cambios en debounce.
- En Windows, el servicio valida antes de escuchar que la raíz de proyectos resuelva a un volumen fijo con bus local reconocido; rechaza UNC, almacenamiento de red y buses USB/SD/MMC, iSCSI, Fibre Channel o desconocidos. Depende del módulo Storage de PowerShell y vuelve a comprobarse al reiniciar; véase [ADR-0017](decisions/ADR-0017-volumen-local-para-proyectos.md).
- Perfiles se revalidan también al leer el archivo local. La configuración se limita a 256 KiB y 50 perfiles. Para cada petición a un proveedor se resuelve DNS, se rechazan direcciones no públicas y el socket usa una función de resolución fijada a las IP ya comprobadas (Undici Agent); se rechazan redirecciones, se aplican timeout y tope de respuesta de 1 MiB. `npm audit --omit=dev` no reporta vulnerabilidades. Falta recorrido de red con proveedores reales y verificación exhaustiva de espacios IPv6 especiales/errores de conexión en Windows.

- El servicio escucha solo en `::1`; el navegador abre la UI en `localhost`, que resuelve al loopback. No acepta conexiones desde la red local.
- La API valida host y origen exactos; no habilita CORS abierto. El nonce de arranque se intercambia una vez por cookie `HttpOnly`, `SameSite=Strict`, como define [ADR-0009](decisions/ADR-0009-sesion-local-segura.md). Las rutas de proyecto exigen sesión; las mutaciones exigen además origen y JSON. Si el navegador omite `Origin` en una petición same-origin, el servidor exige `Sec-Fetch-Site: same-origin` y el encabezado privado de la UI. En desarrollo, Vite entrega un bootstrap de nonce solo al origen configurado. El lanzador genera el nonce y lo pasa en el fragmento; el canje y la carga autenticada se recorrieron en producción temporal. El intercambio no registra nonce/cookie.
- Las claves de proveedor se guardan en Windows Credential Manager mediante `@napi-rs/keyring`; el archivo de perfiles solo contiene configuración no secreta y la API expone un booleano de credencial configurada. No se escriben en proyectos, ADR, capturas o registros. El marcador temporal se verificó ausente del JSON y luego se eliminó del almacén.
- La app envía el mensaje, las etiquetas/relaciones de la rama, un resumen global estructural (idea central y hasta ocho etiquetas de rama, máximo 120 caracteres cada una) y fragmentos de diapositivas enlazadas solo al usar el proveedor activo. Los fragmentos se limitan a 20 diapositivas, 500 caracteres por diapositiva y 6.000 totales; el panel expandible los muestra antes del envío junto al proveedor/modelo, conexión local/remota, proyecto, ideas, relaciones y recuentos omitidos. En chat se agregan hasta 10 mensajes recientes; el panel los muestra con autor y el mismo recorte de 3.000 caracteres por mensaje que aplica el servidor. Al ejecutar una tarjeta de sugerencia se envía su petición sin ese historial. El texto actual del compositor queda visible y la UI informa que se enviará al pulsar «Enviar». Un proveedor remoto recibe esos datos.
- Los registros HTTP eliminan la query de la URL antes de serializar la petición, para evitar exponer el código/estado del callback OIDC; el handler común de errores no registra cuerpo, prompt, credenciales ni mensajes internos. Los eventos de autenticación se guardan en `%LOCALAPPDATA%\EspacioVisual\security-events.jsonl` con hora, tipo, resultado e ID saneado, sin identidad/credenciales/proyectos; retención 30 días, máximo 5.000 líneas y 1 MiB. Es best-effort: un fallo se advierte en el logger, pero no bloquea el acceso. Revisa esta garantía si cambia la configuración del logger.
- La instrumentación de IA registra ID de petición, ruta, UUID opaco de proyecto, tipo de proveedor, etapa, resultado, revisiones y duración. Excluye prompts, respuestas, etiquetas/contenido del mapa, nombres de proyecto, URL de proveedor y secretos. Un recorrido completo con proveedor simulado confirmó eventos de generación/guardado y excluyó marcadores de prompt, mapa y cuerpo upstream de respuestas y logs; véase ADR-0019 y VERIFICATION.md.
- El chat no modifica el proyecto. Las ideas propuestas se validan y permanecen en vista previa hasta la aplicación explícita; el servidor comprueba IDs, alcance y revisión. El modelo no tiene acceso directo al sistema de archivos.
- El proceso se ejecutará bajo la cuenta interactiva que lo inició; proyectos y credenciales no se compartirán mediante un servicio Windows común.

La implementación actual mantiene sesiones en memoria durante un máximo de 12 horas y las pierde al cerrar el servicio. T-020 añadió tipos/cookies separados para sesión local y protegida, revocación/logout con validación de origen y máximo de 128 sesiones. T-021 integra `openid-client`: discovery, Code + PKCE S256, state/nonce, callback loopback y enlace inicial por `(iss, sub)`. El ID/access token no se persiste; una validación correcta crea solo un estado OIDC temporal de cinco minutos. Desde Ajustes se configura OIDC y se puede iniciar el vínculo. `MYMAP_AUTH_MODE` acepta `local` (predeterminado) o `protected`; en `protected`, la API de proyectos/proveedores/IA exige una cookie protegida y el intercambio del nonce local se rechaza. Tras OIDC, `protected` exige WebAuthn con UV y crea la sesión protegida solo tras verificarla. T-023 incorpora parcialmente recuperación TOTP: el secreto y estado anti-replay/bloqueo se guardan en Windows Credential Manager; OIDC + TOTP solo emite una cookie temporal para registrar una passkey, que las rutas de proyecto/proveedor/IA no aceptan. Falta probar IdP, app autenticadora y autenticador reales. El callback OIDC usa el literal IPv6 loopback; su estado temporal se transfiere una sola vez en el fragmento, que la UI elimina antes de canjearlo por cookie en `localhost`. El flujo no se ha verificado con un IdP real. El nonce de desarrollo se puede obtener una vez solo desde el origen configurado; el endpoint se desactiva en `NODE_ENV=production`. `scripts/start-local.ps1` pasa un nonce de producción por `ESPACIO_VISUAL_SESSION_NONCE` y abre la UI con `#session=<nonce>`. Las llamadas de generación usan timeout de 90 segundos y rechazan redirecciones. Si el cliente cancela o cierra la conexión, el servidor aborta la petición HTTP en curso al proveedor; el proveedor remoto/local aún podría continuar cómputo internamente. Este recorrido de cancelación está implementado pero no verificado con una respuesta lenta. Las URLs remotas requieren HTTPS y HTTP solo está permitido en loopback. La auditoría fue de código y dependencia, no un pentest; no verificó exhaustivamente cada criterio OWASP ni comportamiento de todos los proveedores en Windows. El panel de contexto se recorrió con un perfil y datos bajo un `%APPDATA%` temporal; no se envió texto a ningún modelo durante ese recorrido. La revisión estática de autenticación está en [`reviews/2026-11-16-auth-mfa-audit.md`](reviews/2026-11-16-auth-mfa-audit.md), y la operación/desvinculación en [`AUTH_OPERATIONS.md`](AUTH_OPERATIONS.md); no es una prueba de penetración ni certificación WCAG.
